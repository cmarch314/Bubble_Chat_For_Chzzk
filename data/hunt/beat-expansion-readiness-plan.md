# 몬스터 확장 전 BEAT 잠금 계획

## 1. 결론

현재 디아브로스, 에디터, 실수렵, 헌터 BEAT는 기준 모델을 만들 수 있는 단계까지 도달했음. 다만 지금 바로 몬스터를 늘리면 자동 변환된 구형 모션, 프리뷰 전용 타이머, 검증되지 않은 릴리스 체크가 새 몬스터마다 복제될 위험이 큼.

따라서 신규 몬스터 추가 전에 **확장 잠금(Expansion Lock)** 을 먼저 완료함. 디아브로스를 골든 레퍼런스로 고정하고, 소스 데이터 하나가 에디터와 실수렵을 모두 구동하며, 승인 상태가 증거와 일치하도록 만드는 작업임.

신규 몬스터 착수 조건은 0~4단계 완료임. 5~7단계는 확장과 병행할 수 있으나, 미승인 무기나 몬스터를 승인 완료로 표시하면 안 됨.

## 2. 현재 감사 결과

### 확인된 강점

- `HuntBeatV2Contract`와 `HuntBeatActionRuntime`이 몬스터·헌터 행동의 공통 시계 역할을 수행함.
- 실수렵은 `HuntCombatRuntime`과 `HuntCombatClock`을 사용함.
- 에디터 모션 미리보기는 실수렵과 같은 `HuntRenderer`, `HuntMonsterAttackAnimator`, 컴파일된 패턴을 사용함.
- 에디터의 실전 시뮬레이션은 실제 앱 런타임을 사용함.
- 디아브로스와 대검은 현재 가장 높은 수준의 수동 검수·BEAT 작성이 이루어진 기준 구현임.
- 몬스터 감사, 전체 수렵 감사, 50회 시뮬레이션, 전체 검증 명령은 통과함.

### 확장 전 반드시 해결할 결함

1. **승인 의미가 불명확함**
   - `HuntMonsterPatternCatalog`의 자동 동기화·구형 변환 결과도 `beatV2Approved: true`가 될 수 있음.
   - 전체 마이그레이션 테스트는 20마리 221패턴을 승인된 것처럼 통과시키지만, 실제 원본에서 명시적으로 승인된 패턴은 디아브로스 9개뿐임.
   - 헌터 행동 198개 중 명시 승인된 것은 대검 15개이며, 나머지 183개는 범용 휴리스틱으로 생성된 `migrated` 상태임.

2. **프리뷰에 별도 시계가 남아 있음**
   - 모션 자체는 공용 렌더러를 쓰지만 리액션, 함정 허덕임, 비행 전환, 상태 초기화 일부가 프리뷰의 `setTimeout`으로 진행됨.
   - 같은 데이터를 사용해도 시간 소유자가 둘이면 프리뷰와 실수렵이 다시 어긋날 수 있음.

3. **리액션·상태 모션이 완전한 BEAT 그래프가 아님**
   - 소경직, 대경직, 꼬짤, 수면, 구멍함정은 `HuntMonsterReactionCatalog`의 모션 배열과 런타임 보조 로직으로 구성됨.
   - 공격 패턴과 같은 취소·완료·사운드·이벤트 계약을 보장하기 어려움.

4. **릴리스 게이트가 증거를 검증하지 않음**
   - 몬스터 키트의 `evidence`, `animation`, `audio`, `preview`, `simulation`은 현재 불리언만 검사함.
   - 디아브로스 노트에는 1920×1080 시각 검수 미완료 항목이 남아 있지만 키트는 완료로 표시됨.

5. **확장 소스가 단일 대형 파일에 집중됨**
   - `HuntMonsterProfiles.js`에 32마리 279패턴이 함께 있음.
   - 200마리 이상으로 확장하면 충돌, 리뷰 범위, 생성물 병합 비용이 급격히 증가함.

6. **현재 기준선 테스트 3건이 실패함**
   - `hunt-diablos-runtime.test.js`: 흑디아 뿔 돌진 상속 피해 배율 기대값 불일치.
   - `hunt-monster-part-material-catalog.test.js`: 단색 `color` 기대와 현재 `palette` 계약 불일치.
   - `layout-contracts.test.js`: 최근 헌터 피격 표시 구조와 오래된 선택자 기대가 불일치.

이 세 건은 실제 회귀인지 낡은 테스트인지 각각 판정한 뒤 수정해야 함. 실패를 삭제하거나 기대값만 무근거로 바꾸면 안 됨.

## 3. 목표 구조

```text
몬스터 키트 소스
  ├─ 메타데이터/증거/릴리스 상태
  ├─ 해부·부위 데이터
  ├─ 승인된 행동 BEAT 그래프
  ├─ 리액션·상태 BEAT 그래프
  └─ 음성 라우트 참조
          │
          ▼
결정적 컴파일러 + 계약 검증
          │
          ├─ 에디터 모션 전용 미리보기
          │    └─ 같은 그래프/시계, 게임 판정만 표시 전용으로 비활성
          │
          └─ 실전 시뮬레이션·실수렵
               └─ 같은 그래프/시계/판정/사운드/취소 규칙
```

핵심 원칙은 다음과 같음.

- 작성 데이터는 한 번만 존재함.
- 자동 변환은 `migrated`, 사람이 검수한 그래프만 `approved`임.
- 렌더러는 시간을 만들지 않고 현재 틱을 그림.
- 판정, 사운드, 이펙트, 이동, 복귀, 완료는 같은 행동 세션에 속함.
- 프리뷰는 실수렵의 복제품이 아니라 같은 모듈의 모션 전용 실행 모드임.
- 몬스터 ID 분기는 실행기에서 금지하고 키트 데이터와 공용 정책으로 표현함.

## 4. 단계별 실행 계획

### 0단계 — 기준선 고정

**담당 권장:** Terra
**목표:** 현재 상태를 거짓 양성 없이 재현 가능한 녹색 기준선으로 만듦.

작업:

1. 위 3개 실패 테스트를 코드와 현재 승인 설계에 대조함.
2. 실제 회귀면 런타임 수정, 낡은 계약이면 테스트와 소유권 문서를 함께 수정함.
3. 디아브로스 9개 승인 공격, 공용 리액션, 대검 15개 행동의 다음 값을 스냅샷으로 고정함.
   - 총 틱
   - BEAT 구간과 종료 틱
   - 판정 종류·틱·대상 프리셋·피해·리액션 크기
   - 사운드 순간
   - 이동 종료 위치·회전·반전
   - 취소 가능 시점과 복귀 완료
4. 테스트 출력에 사용한 소스 리비전과 컴파일 해시를 기록함.

완료 조건:

- 관련 집중 테스트 전부 통과.
- 실패 원인과 수정 근거가 커밋 메시지와 테스트 이름으로 추적 가능함.
- 골든 스냅샷이 자동 생성 시 무의미하게 갱신되지 않음.

권장 커밋: `test(hunt): lock beat expansion baseline`

### 1단계 — 승인 상태를 3단계로 분리

**담당 권장:** Terra
**선행:** 0단계

상태:

- `draft`: 작성 중이며 실행·릴리스 불가.
- `migrated`: 구형 자료나 휴리스틱으로 변환됨. 참고·미리보기 가능, 승인 릴리스 불가.
- `approved`: 사람이 에디터와 실전 시뮬레이션으로 검수했고 증거가 연결됨.

작업:

1. `beatV2Approved` 불리언을 명시적 리뷰 상태로 대체함. 과도기에는 읽기 호환만 허용함.
2. `synchronizeMotionTiming`, `legacyTimingBeats`, 범용 헌터 그래프가 절대 `approved`를 만들지 못하게 함.
3. 릴리스 카탈로그는 `approved`만 승인 경로로 로드함.
4. `migrated`는 CSS·구형 타이밍 실행을 되살리는 의미가 아니라, BEAT로 변환됐지만 시각 검수가 끝나지 않았다는 의미로 고정함.
5. 테스트가 원본 소스의 상태를 검사하도록 수정함. 런타임 정규화 결과만 검사하면 안 됨.

완료 조건:

- 자동 변환 함수에서 승인 상태 생성 0건.
- 디아브로스·대검만 현재 승인 목록으로 나타남.
- 미승인 패턴의 릴리스 시도는 패턴 ID와 사유를 포함해 실패함.

권장 커밋: `refactor(hunt): make beat approval evidence based`

### 2단계 — 몬스터별 작성 패키지와 결정적 컴파일

**담당 권장:** Terra
**선행:** 1단계

권장 배치:

```text
data/hunt/monster-kits/<id>.json              # 메타데이터·단계·증거·참조
data/hunt/monster-kits/actions/<id>.json      # 공격·상태·리액션 BEAT 작성 소스
data/hunt/monster-kits/notes/<id>.md          # 조사·인터뷰·미해결 결정
js/effects/hunt/data/*.generated.js           # 결정적 런타임 생성물
```

작업:

1. 디아브로스를 첫 패키지로 추출함.
2. 키트에 `actionsRef`, `anatomyRef`, `audioEvidenceRef`, `compiledHash`를 둠.
3. 컴파일러가 스키마, 참조, 승인 상태, 판정 대상, 사운드 순간, 총 틱을 한 번에 검증함.
4. `HuntMonsterProfiles.js`는 호환 파사드로 축소한 뒤, 모든 몬스터 이전 후 제거함.
5. 생성 파일은 도구로만 갱신하고 직접 편집을 금지함.
6. 한 몬스터 변경이 다른 몬스터 생성 결과를 바꾸면 테스트가 실패하도록 함.

완료 조건:

- 디아브로스 작성 소스가 단일 패키지에 존재함.
- 에디터와 실수렵이 같은 컴파일 결과를 로드함.
- 동일 입력의 생성 해시가 반복 실행에서 동일함.
- 실행기·정책에 `diablos` ID 분기 추가 없음.

권장 커밋: `refactor(hunt): compile diablos from a monster action package`

### 3단계 — 리액션·상태·환경을 BEAT로 통합

**담당 권장:** Terra
**선행:** 1단계. 2단계와 핫 파일이 겹치므로 직렬 작업 권장.

대상:

- 소경직, 대경직, 꼬짤경직
- 기절, 마비, 수면 진입·유지·기상
- 구멍함정 지반 붕괴·허덕임 반복·탈출·그물 Fade Out
- 포효, 풍압, 지진 같은 비피해 판정
- 부위파괴 이미지·공통 SE 레이어
- 수레, 피격 복귀 등 헌터 리액션

작업:

1. 공용 `actorType`을 최소 `monster-action`, `monster-reaction`, `hunter-action`, `hunter-reaction`, `environment`로 정의함.
2. 모두 `HuntBeatActionRuntime`의 실행·취소·완료 계약을 사용함.
3. 반복 허덕임이나 수면 루프도 BEAT 반복 구간으로 표현하고 DOM 타이머를 만들지 않음.
4. 에디터 fixture의 리액션·함정·상태 `setTimeout`을 제거함.
5. 부위파괴는 현재 행동을 취소할지, 시각·SE만 겹칠지 상태 규칙으로 명시함.
6. 우선순위와 큐 규칙을 표로 고정함.
   - 공격 중 분노 전환: 현재 행동 완료 후 전환 포효.
   - 무효 상태 중 부위파괴: 이미지·SE만 실행, 새 경직은 억제.
   - 기절 중 대경직: 억제.
   - 승인된 강제 중단: 기존 세션 판정·사운드·타이머 전부 취소.

완료 조건:

- 검토 대상 코드에서 행동·리액션 진행용 `setTimeout` 0건.
- 함정·수면·대경직의 프리뷰와 실수렵 이벤트 틱이 동일함.
- 취소된 행동에서 후발 판정·사운드·복귀가 발생하지 않음.

권장 커밋: `refactor(hunt): run reactions and controls on the beat clock`

### 4단계 — 프리뷰/실수렵 패리티 하네스

**담당 권장:** Terra
**선행:** 2~3단계

작업:

1. 공용 `CompiledActionSession` 입력을 정의함.
   - 패턴 ID
   - 상태 스냅샷
   - 주 대상 또는 2인·전원 대상 시나리오
   - 부위 상태
   - 난수 시드
2. 에디터와 실수렵이 같은 세션 팩토리를 호출함.
3. 모션 전용 미리보기는 피해 계산만 비활성화하고 이벤트 표시는 유지함.
4. 다음 트레이스를 양쪽에서 수집해 완전 일치시킴.
   - 각 틱의 위치·회전·스케일·반전
   - 판정과 대상
   - 사운드 이벤트
   - 상태 전환
   - 완료·취소·복귀
5. 디아브로스 모든 승인 행동에 1인·2인·4인, 분노, 부위파괴, 중단 시나리오를 적용함.
6. 에디터 UI는 트레이스의 현재 틱만 렌더링하며 별도 판정을 발명하지 않음.

완료 조건:

- 동일 입력에서 프리뷰와 실수렵 트레이스가 완전 일치함.
- 에디터 재생 성능을 위해 판정을 생략해도 표시 이벤트의 틱과 대상은 동일함.
- 패턴 선택만으로 이펙트·사운드·판정이 실행되지 않음.

권장 커밋: `test(hunt): enforce preview and live action parity`

### 5단계 — 디아브로스 골든 릴리스 확정

**담당 권장:** Luna 시각 검수, Terra 결함 수정
**선행:** 0~4단계

Luna가 없으면 Terra가 동일 체크리스트를 수행함. 시각 판단과 코드 수정을 한 커밋에 섞지 않음.

검수 환경:

- 1920×1080
- 1인·2인·4인 대상
- 일반·분노·탈진
- 각 부위 파괴 전후
- 함정·기절·수면·대경직 중단
- 프리뷰 모션 모드와 실전 시뮬레이션 동시 비교

반드시 닫을 항목:

- 지중잠행 상승 시작 이후 출현 위치 고정.
- 분노 연속돌진에서 복귀·후방 X자 꼬리 연계가 끊김 없이 재생.
- 모든 판정 마커와 실제 대상 일치.
- 모든 사운드가 작성 순간에만 한 번 재생.
- 복귀 완료 전 다음 패턴·분노 포효·상태 전환 없음.

완료 조건:

- `notes/diablos.md`의 미완료 항목 0개.
- 키트의 각 릴리스 게이트에 테스트 ID, 검수 날짜, 소스 해시가 연결됨.
- 디아브로스가 다른 몬스터 작업의 복사 대상이 아니라 계약 예제로 사용됨.

권장 커밋: `docs(hunt): approve diablos as the beat golden reference`

### 6단계 — 헌터 무기 승인 순서

**담당 권장:** Terra 구현, Luna 시각 검수
**선행:** 1·3·4단계

현재 대검만 승인 상태로 유지함. 나머지는 `migrated`로 명확히 노출함.

권장 순서:

1. 카운터·방어 고위험군: 태도, 랜스, 건랜스, 차지액스, 슬래시액스.
2. 근접 콤보군: 한손검, 쌍검, 해머, 피리, 조충곤.
3. 원거리군: 라이트보우건, 헤비보우건, 활.

무기별 승인 조건:

- 모든 행동이 명시 BEAT이며 범용 분할 휴리스틱을 사용하지 않음.
- 성공·실패 카운터가 서로 다른 판정 결과를 가짐.
- 피격 무적은 헌터 리액션 소유자만 부여함.
- 날 방향, 대상 좌우, 궤적, 자원, 콤보, ATB, 취소가 테스트됨.
- 프리뷰/실수렵 트레이스가 일치함.

### 7단계 — 신규 몬스터 온보딩 파이프라인

**담당 권장:** Terra 자료·구현, Luna 시각 검수

한 몬스터는 다음 순서를 반드시 따름.

1. 원작 근거 수집과 `notes/<id>.md` 작성.
2. 공통 규칙과 고유 규칙 분리.
3. 패턴·상태·부위·리액션 목록 확정.
4. `actions/<id>.json`을 `draft`로 작성.
5. 에디터에서 궤도·판정·사운드·복귀 검수.
6. 상태 조합과 중단 시나리오 검수.
7. 실전 시뮬레이션 패리티·50회 밸런스 검증.
8. 증거가 연결된 항목만 `approved`로 승격.
9. 골든 게이트 통과 후 릴리스.

중간 결과를 승인으로 표시하지 않으며, 한 몬스터가 통과하기 전 다음 몬스터를 같은 핫 파일에서 동시에 작업하지 않음.

## 5. 릴리스 게이트 v2

불리언 대신 아래 증거 객체를 사용함.

```json
{
  "status": "approved",
  "sourceRevision": "<hash>",
  "verifiedAt": "YYYY-MM-DD",
  "checks": ["<test-or-review-id>"],
  "reviewer": "human-or-agent-role",
  "notes": "<remaining-risk-or-empty>"
}
```

필수 게이트:

- `evidence`: 원작 근거와 인터뷰 결정이 연결됨.
- `schema`: 모든 참조와 이벤트가 유효함.
- `motion`: 총 틱, 이동, 회전, 반전, 복귀가 승인됨.
- `judgments`: 피해·비피해 판정과 대상이 승인됨.
- `audio`: 모든 라우트가 근거를 가지며 누락은 무음으로 명시됨.
- `reactions`: 부위·상태·중단 규칙이 승인됨.
- `previewParity`: 모션 프리뷰 트레이스가 공용 세션과 일치함.
- `liveParity`: 실전 시뮬레이션 트레이스가 일치함.
- `balance`: ATB, 피해, 스테미너, 패턴 비율이 시뮬레이션을 통과함.
- `visual1920`: OBS 1920×1080 검수가 완료됨.

## 7. Terra/Luna 작업 패킷 규칙

각 작업 요청에 아래를 그대로 포함함.

```text
목표:
선행 커밋:
허용 파일:
금지 파일/행동:
현재 실패 재현 명령:
구현 계약:
완료 조건:
필수 테스트:
시각 검수 시나리오:
커밋 메시지:
남은 위험 보고 형식:
```

### 모델 역할 권장

- **Terra:** 소유권 정리, 스키마, 컴파일러, 런타임, 테스트, 결정적 마이그레이션.
- **Luna:** 1920×1080 시각 검수, 동작 궤도·타격감·가독성 비교, 재현 가능한 결함 목록 작성.
- Luna는 런타임 핫 파일을 직접 대규모 수정하지 않고 틱·좌표·판정·화면 증거를 전달함.
- Terra는 시각 지적을 데이터와 공용 계약으로 수정하며 Preview 전용 보정을 만들지 않음.

### 병렬 작업 금지 구역

다음 파일·영역은 한 번에 한 작업자만 수정함.

- `HuntBeatV2Contract`, `HuntBeatActionRuntime`
- `HuntMonsterPatternCatalog`, `HuntMonsterProfiles`
- `HuntCombatRuntime`, `HuntMonsterTurnExecutor`
- `HuntMonsterReactionCatalog`
- 에디터 세션·프리뷰 fixture
- 생성 카탈로그와 오디오 라우트

서로 다른 워크트리와 브랜치를 사용하고, 생성 파일은 원본 변경 후 도구로 재생성함.

## 8. 금지 사항

- 신규 몬스터 수를 먼저 늘리고 나중에 승인 구조를 고치지 않음.
- 정규화·마이그레이션 함수에서 `approved`를 자동 생성하지 않음.
- 실행기에서 몬스터 ID 하드코딩을 추가하지 않음.
- 에디터 전용 판정·사운드·타이머를 만들지 않음.
- 검수된 행동의 실행 소유자로 CSS keyframe을 되살리지 않음.
- `hitOffsetTicks`, `judgmentOffsets`, phase-slot 오디오를 새 데이터에 추가하지 않음.
- 생성 파일을 직접 수정하거나 수동 병합하지 않음.
- 테스트를 통과시키기 위해 근거 없이 기대값을 변경하지 않음.
- 증거 없는 릴리스 게이트를 `true`로 두지 않음.

## 9. 신규 몬스터 시작 판단

다음 질문이 모두 예일 때만 시작함.

- 자동 변환된 패턴과 승인 패턴이 명확히 구분되는가?
- 디아브로스 골든 테스트가 전부 통과하는가?
- 프리뷰와 실수렵이 같은 세션·그래프·틱을 쓰는가?
- 공격뿐 아니라 리액션·함정·상태도 BEAT가 소유하는가?
- 몬스터별 소스가 독립되어 다른 몬스터와 충돌하지 않는가?
- 키트 릴리스 게이트가 실제 증거를 검증하는가?
- 한 명령으로 전체 확장 게이트를 재현할 수 있는가?

하나라도 아니오면 해당 단계부터 먼저 완료함.
