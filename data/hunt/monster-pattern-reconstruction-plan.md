# 몬스터 패턴 재건 명세

## 목적

BubbleChat의 몬스터 전투를 원작의 관찰 가능한 행동, 조건, 공간 판정과 대응법에 근거해 재건한다.
원시 액션명이나 히트 데이터가 존재한다는 이유만으로 런타임 기술을 만들지 않는다.

## 기준 작품

- 작품별 패턴 세트는 서로 덮어쓰지 않고 모두 보존한다.
- 기본 런타임은 해당 몬스터가 등장한 최신 본가 액션 게임의 검증 완료 세트를 사용한다.
- 파생작 세트는 별도로 보존한다.
- 원종, 아종, 특수개체, 주인, 괴이 극복, 수호룡은 독립 개체로 관리한다.
- 구작에서 삭제된 상징 기술은 구작 세트에 남기되 최신 기본 세트에 자동 혼합하지 않는다.

## 증거 등급

1. 실제 플레이 영상과 연결된 게임 액션·모션·히트 데이터
2. 공식 설명 또는 공식 영상에서 확인되는 행동
3. TA 영상, 프레임 분석, 모더 분석과 내부 데이터의 교차 확인
4. 일본어 공략·위키·TA 자료의 상호 일치
5. 화면 동작만 검증된 경우 영상 시점과 설명형 임시명

내부 액션명, 히트박스명, 피해표 하나만으로는 행동 의미를 확정하지 않는다.

### 언어권 우선순위

일본어 웹 자료를 기본 조사 원전으로 삼는다. 일본어권은 작품별 기술 변화, 통용 기술명, 행동 조건, 부위 파괴 영향과 실전 대응을 가장 세밀하게 기록하는 경우가 많으므로 먼저 충분히 조사한다.

1. 일본 공식 자료, 게임 내 문구와 공식 가이드
2. 일본 데이터베이스, 검증형 위키와 대사전
3. 일본 TA·프레임 분석·검증 영상과 모더 자료
4. 일본 공략 사이트와 커뮤니티의 반복 관찰
5. 한국어·영어 공식 자료, 위키, 영상과 커뮤니티

한국어와 영어 자료는 일본어 자료의 단순 번역본으로 취급하지 않는다. 일본어권에서 빠진 최신 변경점, 지역별 명칭, 영상 증거 또는 상충되는 관찰을 찾는 보완·반증 자료로 사용한다. 일본어 자료끼리도 서로 베낀 문서일 수 있으므로 독립된 출처 수를 확인하고, 위키 서술만으로 조건이나 수치를 확정하지 않는다.

### 자료군별 역할

가이드 페이지 하나로 패턴을 확정하지 않는다. 몬스터별 조사표는 가능한 모든 자료군을 분리해 기록한다.

- 공식 자료: 생태, 대표 행동, 상태와 작품 버전 확인
- 게임 데이터베이스: 모션값, 상태이상, 가드, 부위와 원시 액션 후보 확인
- 일본어 위키·대사전: 작품별 변경점, 통용 기술명과 오래된 행동 이력 확인
- 영어 위키: 작품 간 비교와 해외 통용 명칭 확인
- 한국어 위키·커뮤니티: 자연스러운 한국어 명칭과 국내 플레이 관찰 확인
- TA·고난도 플레이 영상: 전조, 연계 횟수, 후딜, 위치와 대응 가능 구간 확인
- 일반 플레이 영상: TA에서 생략되기 쉬운 저빈도 행동과 실패 상황 확인
- 모더·데이터마이닝 자료: 액션 클래스, 상태 전이, 히트박스와 내부 조건 후보 확인
- 커뮤니티 토론: 악명 높은 기술, 체감 위험도, 드문 분기와 작품별 차이의 조사 단서 확보

커뮤니티 주장은 단독으로 수치나 조건을 확정하는 근거로 사용하지 않는다. 영상, 내부 데이터 또는 서로 독립적인 복수 관찰과 교차 확인한다.

### 다국어 조사 기록

각 근거 레코드는 다음을 보존한다.

- 언어와 커뮤니티
- URL, 게시일과 확인일
- 영상 타임스탬프 또는 게시물의 해당 주장 요약
- 확인하려는 기술·상태·조건
- 직접 관찰, 작성자 주장, 데이터마이닝 중 증거 종류
- 다른 자료와의 일치·충돌
- 최종 채택 여부와 이유

## 조사 절차

1. 일본어 정식명, 통용명, 내부 액션 검색어와 작품별 별칭을 먼저 수집하고 한국어·영어 이름을 연결한다.
2. 최신작과 작품별 변형 개체를 확정한다.
3. 일본 공식 자료와 데이터베이스에서 기술, 상태, 연계, 부위 파괴와 대응법의 기준 후보를 만든다.
4. 일본 위키·대사전·TA·모더 자료와 커뮤니티를 반복 검색해 조건과 예외를 교차 확인한다.
5. 한국어·영어 자료에서 누락, 최신 변경, 명칭과 상충 관찰을 보완한다.
6. 영상에서 전조, 이동, 공격, 후속타, 회복까지 하나의 완성 행동을 확인한다.
7. 내부 모션과 히트 데이터를 화면 행동에 연결한다.
8. 발견하지 못한 항목은 추측하지 않고 미해결 보고서에 남긴다.

미해결 보고서는 검색어, 언어, 확인한 사이트, 발견한 원시 데이터, 부족한 근거와 다음 조사 경로를 기록한다.

## 기술 단위

- 플레이어가 하나의 공격으로 인식하는 완성 동작을 한 기술로 취급한다.
- 준비 판정, 신체 판정, 폭발 판정을 별도 기술로 분리하지 않는다.
- 후속 공격의 방향, 대응법 또는 상태 조건이 달라질 때만 별도 분기로 둔다.
- 원작의 반복 연계는 반복 횟수와 중단 조건을 가진 하나의 콤보로 구성한다.
- 고정된 최소 패턴 수나 최대 패턴 수를 두지 않는다.

## 행동 그래프

기술 목록의 평면 가중치 추첨을 금지한다. 각 몬스터는 다음 상태를 사용하는 조건부 행동 그래프를 가진다.

- 거리, 방향, 헌터의 밀집도
- 지상, 비행, 잠복, 투명화
- 평상, 분노, 탈진과 몬스터 고유 상태
- 부위 파괴 전후
- 연계 시작, 반복, 후속타, 마무리
- 공개되지 않는 내부 전술 단계와 시간 기반 공격성 변화
- 준비 행동, 공격, 초과 이동, 복귀, 회복

내부 전술 단계는 UI에 표시하지 않고 행동 변화로만 관찰할 수 있게 한다.

## 공간과 공격 전달

UI와 전투 좌표를 분리한다. 이름, 체력, ATB, 퍽과 아이템 UI는 고정하고 무기 이미지와 전투 이펙트만 독립 좌표를 사용한다.

공격 대상은 임의의 최대 대상 수가 아니라 공격 형상과 헌터 좌표의 교차로 결정한다.

- 단일 조준
- 직선 관통
- 부채꼴
- 방사형
- 포물선 낙하
- 지면 장판
- 경로 잔류
- 공중 폭격
- 실제 전역 판정

공격 전달 유형은 다음을 구분한다.

- 단발·연속·확산·포물선 투사체
- 짧은 분사, 횡방향 훑기, 부채꼴 브레스
- 검증된 지속형 레이저
- 독무, 수면가스, 분진
- 장판과 틱 피해
- 경로에 남는 화염, 점액, 폭린
- 낙하 폭격
- 지면·시간차 폭발
- 설치형 지뢰, 비늘, 결정

`빔 형태 히트 데이터`는 화면에서 광선이 확인되지 않으면 레이저로 분류하지 않는다.

## 돌진과 이동

일반 돌진은 다음 수명주기를 가진다.

`전조 → 가속 → 진형 관통 → 초과 이동 → 감속·방향 전환 → 복귀 → 회복`

- 피해는 실제 통과 시점에 발생한다.
- 화면 밖에서 원위치로 순간이동하지 않는다.
- 왕복 공격은 원작에 존재할 때만 복귀 중 판정을 가진다.
- 벽 충돌이나 부위 파괴 조건은 넘어짐과 대경직으로 분기한다.

## 다단 공격

- 각 타격은 위치, 시간, 피해와 상태 판정을 별도로 가진다.
- 첫 피격 후 넘어짐, 구속, 무적과 후속타 관계를 보존한다.
- 가드 부담은 타격마다 누적한다.
- 긴급회피 무적시간이 실제 전체 판정 구간을 덮는지 검사한다.
- 전체 위험도는 전타 적중 피해를 함께 기록한다.

## 부위 파괴

부위 파괴 후 기술을 일괄 삭제하지 않는다. 작품별 원작 행동에 따라 다음 중 하나를 사용한다.

- 피해, 사거리, 경직치 약화
- 속성 또는 상태이상 제거
- 설치물·투사체 수 감소
- 공격 판정 없는 헛동작과 긴 회복
- 다른 행동으로 변형
- 신체 구조상 불가능한 경우에만 사용 불가

변화는 파괴 순간의 짧은 알림 외에는 텍스트로 설명하지 않는다. 파손 이미지, 줄어든 입자, 짧아진 궤적과 달라진 빈틈으로 관찰하게 한다.

## 피해 평가

게임별 원시 수치를 직접 복사하지 않는다. 다음 근거로 상대적 위험도를 정한다.

- 모션값과 다단 수
- 가드 가능 여부와 부담
- 범위와 추적
- 전조와 회피 난이도
- 상태이상과 지속 피해
- TA·공략·커뮤니티 평가
- 실제 즉사기 취급 여부

위험도는 `견제`, `일반`, `강공격`, `치명상`, `즉사급`으로 기록하고 BubbleChat 체력 체계에 맞게 환산한다.
모든 몬스터에게 광역기, 강력한 연계 또는 필살기를 강제로 만들지 않는다.

## 치명적 패턴과 자동 대응

- 모든 치명적 패턴에는 원작에 맞는 정답이 존재해야 한다.
- 긴급회피, 대경직, 부위 파괴, 섬광, 상태이상, 아이템, 엄폐와 환경 기믹 중 유효한 대응만 등록한다.
- 유효하지 않은 대응도 명시해 범용 회피를 잘못 선택하지 않게 한다.
- 준비 실패로 대응 자원을 소진했다면 전조 시점의 패배가 확정될 수 있다.
- 무작위로 처음부터 해답이 없는 전투 상태는 생성하지 않는다.

AI는 전투 전반에서 대응 자원을 관리한다. 성향은 유효 대응의 선택 가중치와 자원 보존 판단을 바꾸지만 정답 확률을 0으로 만들지 않는다.
파티 단위 관리자는 덫, 섬광, 낙석과 폭탄의 중복 사용을 방지한다.

## 표시명

- 몬스터 이름 접두사, 랭크, 단계 번호와 개발용 접미사를 제거한다.
- 공식 한국어명, 검증 번역명, 설명형 임시명을 내부에서 구분한다.
- UI에는 자연스러운 이름만 전조 시작 시 한 번 표시한다.
- 숨은 페이즈, 대응 정답과 확률은 UI에 공개하지 않는다.

금지 예:

- `[MR]`, `【MR】`, `_MR`
- 조룡용, 테스트, 히트 데이터, 판정용
- 근거 없는 `레이저`
- 행동을 식별하지 못하는 `근접 강타`, `광역 강타`, `특수 행동`

## 애니메이션과 사운드

가속, 감속, 이동, 회전, 착지, 입자와 화면 흔들림은 저수준 부품으로 공유한다.
전조, 경로, 반복, 판정, 복귀, 회복, 부위 파괴 변화와 이펙트 조합은 기술별로 작성한다.

사운드는 정확한 기술 이벤트, 동일 기술 계열, 같은 몬스터의 범용 행동음 순서로 연결한다.
근거 없는 레이저·폭발음을 대신 넣지 않는다. 포효는 검증된 단일 음성만 재생한다.

효과는 큐에 누적하지 않는다. 동시에 필요한 레이어만 합성하고 수명이 끝나면 즉시 제거한다.
입자와 투사체 DOM은 풀링하며 수렵 종료 시 효과, 타이머와 오디오를 모두 폐기한다.

## 점진적 교체

1. 내부 UI 문구와 검증 없는 레이저를 막는 공통 안전장치를 먼저 적용한다.
2. 원시 데이터는 삭제하지 않는다.
3. 검증 완료된 몬스터 세트만 원자적으로 교체한다.
4. 미완성 몬스터는 기존 세트를 유지하되 감사 보고서에 남긴다.
5. 시범 승인 후 같은 골격 또는 행동 계통을 5~8마리씩 처리한다.

## 완료 조건

몬스터 한 마리는 다음 항목이 모두 끝나야 재건 완료로 집계한다.

- 최신작과 작품별 조사
- 세 언어권 출처와 영상 시점
- 완성 행동과 조건 그래프
- 부위 파괴 변화
- 유효·무효 대응과 자원
- 공간·다단 판정과 피해 평가
- 애니메이션·이펙트·사운드

## 확인된 현행 오류

- Rise 런타임 626개 패턴 중 랭크 문자열이 남은 항목 15개.
- 조룡용, 히트 데이터, 테스트, 판정용 성격의 원시 항목이 대표 기술로 선발됨.
- 오나즈치의 `固定長ビーム状毒霧ヒットデータ`를 화면 검증 없이 `레이저`로 표시.
- 바젤기우스의 내부 `ブレス` 항목을 폭린 점화 동작과 구분하지 않고 독립 브레스로 표시.
- 대표 기술을 의미 없이 `근접 강타`, `광역 강타`, `돌진`, `꼬리`로 축약.
- 기존 검증은 이름, 피해 범위와 출처 문자열만 검사하여 의미 오류를 통과시킴.
